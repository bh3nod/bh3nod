These days I spend most of my time on one question: **how much of engineering and operations can AI
agents do end to end, and how do you trust them with it?** My answer so far is boring on purpose —
agents do the work, policy sets the limits, humans approve what matters, and everything leaves an
audit trail. I care less about impressive demos and more about what still works at 3 a.m. when
something breaks.

### What I'm into right now

- **Agentic AI:** agents that don't just answer questions but do the work: open the PR, run the
  runbook, triage the incident, roll back the release.
- **Agent harnesses:** the unglamorous part that makes agents useful: tools, sandboxes, permissions,
  memory and evals. A good harness matters more than a clever prompt.
- **Automating everything:** if I've done something twice by hand, I want an agent doing it the
  third time.
- **Guardrails:** policy, approvals and audit trails, so automation is something you can actually
  trust in production.
- **Security for agentic AI:** treating every agent like a new team member with production access.
  That means its own least-privilege identity, short-lived credentials, sandboxed tools, defenses
  against prompt injection, and a clear record of what it did and why.
